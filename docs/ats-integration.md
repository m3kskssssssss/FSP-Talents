# Интеграция с ATS работодателей (концепция)

За рамками MVP. Цель (ответ экспертов FTT.5): платформа встраивается в существующий процесс найма работодателя, а не требует вручную дублировать данные между системами.

## Что синхронизируем

| Сущность платформы | Объект в ATS (Huntflow, Talantix, Potok, SAP SF и др.) | Направление |
|---|---|---|
| Потребность `needs` / вакансия `vacancies` | Вакансия | ATS → платформа (импорт), платформа → ATS (создание) |
| Принятое приглашение / принятый отклик | Кандидат на вакансии + резюме PDF | платформа → ATS |
| Статусы `invitation_events`, `applications.status` | Этапы воронки | в обе стороны |
| Результат теста и категория | Комментарий / кастомное поле кандидата | платформа → ATS |
| Отказ, оффер, выход на работу | Этап «отказ / оффер / нанят» | ATS → платформа (для качества подбора) |

**Контакты передаются в ATS только после согласия кандидата**: после принятия приглашения или собственного отклика. До этого ATS получает обезличенную карточку, так работает правило ТЗ о раскрытии контактов.

## Архитектура

```mermaid
flowchart LR
  P[Платформа: invitation_events, applications] -->|outbox| Q[(очередь событий)]
  Q --> A1[Адаптер Huntflow]
  Q --> A2[Адаптер Talantix]
  Q --> A3[Generic webhook]
  A1 & A2 & A3 -->|REST API ATS| ATS[ATS работодателя]
  ATS -->|webhook смены этапа| H[/api/v1/integrations/{provider}/webhook/]
  H --> P
```

- **Outbox-паттерн.** Каждое изменение статуса уже пишется в `invitation_events`. Отдельная таблица `integration_outbox` получает событие в той же транзакции. Воркер доставляет его адаптеру с повторами и идемпотентным ключом. Событие не теряется, даже если ATS недоступна.
- **Адаптер на каждую ATS** реализует общий интерфейс `pushCandidate`, `pushStage`, `importVacancies`, `parseWebhook`. Маппинг этапов хранится в настройках работодателя: «принято» → «Первичное интервью».
- **Generic webhook** для ATS без готового адаптера: работодатель указывает URL, платформа шлёт подписанные (HMAC) события в стандартном JSON.
- **Подключение**: OAuth 2.0 там, где ATS его поддерживает, иначе API-ключ. Токены шифруются, доступ к ним — только у сервиса интеграций.
- **Обратная связь в подбор**: исходы из ATS («оффер», «нанят», «отказ после интервью») — разметка для обучения весов ранжирования (learning-to-rank) с сохранением объяснимости.

## Что уже есть в MVP

- Полная история статусов приглашений в `invitation_events` — готовый источник событий.
- Стандартизированный PDF-профиль кандидата (`GET /api/v1/me/resume.pdf`) — вложение для карточки в ATS.
- OpenAPI-описание всего API (`/api/docs`) — работодатель может забирать данные сам.

## 152-ФЗ

Передача персональных данных в ATS — это передача третьему лицу (работодателю-оператору). Поэтому нужны отдельная строка в согласии кандидата и реестр получателей. В журнал доступа кандидата (`GET /me/access-log`) попадает и выгрузка в ATS.
