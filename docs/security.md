## Аутентификация и сессии

- Пароли: **argon2id** (19 МиБ, t = 2, p = 1). При неизвестном email выполняется фиктивная проверка, чтобы по времени ответа нельзя было определить, есть ли аккаунт.
- Подтверждение email: одноразовый токен (в БД хранится только SHA-256), срок 48 часов. До подтверждения вход запрещён.
- Сессии Auth.js v5 — JWT в httpOnly cookie (secure в проде). CSRF — встроенная защита Auth.js для форм входа. Server actions Next.js проверяют Origin.
- Роли проверяются в `middleware.ts` (разделы) и **в сервисах**: роль и признак удаления перечитываются из БД на каждом запросе.
- Rate limit: вход (10 за 15 мин на email), регистрация (10 в час на IP), приглашения (60 в час и 30 в сутки на работодателя), LLM-эндпоинты (30 в час). Upstash Ratelimit при наличии ключа; иначе in-memory. **Ограничение:** на serverless in-memory лимит действует в пределах инстанса, поэтому суточный лимит приглашений считается по БД.
- Заголовки: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Permissions-Policy`; COOP/COEP только на странице теста.

## 152-ФЗ

- Явные согласия с **версией и датой** (`consents`): обработка ПДн и политика конфиденциальности обязательны, рассылка — по желанию. Отзыв согласия на обработку ПДн убирает кандидата из подборок.
- Политика обработки ПДн — отдельная страница `/privacy`.
- **Минимизация:**
  - работодатель видит маскированное имя и не видит контактов до согласия кандидата;
  - журнал попытки хранит длину вставки, но не содержимое буфера обмена;
  - в логах приложения нет ПДн: почтовый логгер скрывает адресата, ошибки Auth.js не логируют email;
  - **в LLM не уходят ФИО и контакты** (`server/llm/redact.ts`). ФИО, email, телефон, Telegram и ссылки на профили извлекаются из резюме локальными правилами и сразу пишутся в защищённую таблицу. Модель получает текст с метками `[ИМЯ]`, `[EMAIL]`, `[PHONE]`, `[TELEGRAM]`, `[LINK]`, `[ДАТА РОЖДЕНИЯ]` и не возвращает эти поля вовсе (их нет в схеме ответа). Из текста вакансии так же убираются контакты рекрутера. Перефразирование доводов получает только сами доводы, без имени. Это минимизация, а не полная анонимизация: свободный текст может содержать косвенные сведения (места работы, даты), поэтому модель выбирается из рекомендованных организаторами, а без ключа все функции работают на правилах.
- **Журнал доступа к контактам** (`audit_log`: `contacts.disclosed`, `contacts.viewed`) доступен кандидату в разделе «Приватность».
- **Удаление аккаунта с анонимизацией:**
  - email заменяется, пароль удаляется;
  - ФИО, город, «о себе», ФСП ID обнуляются;
  - контакты, навыки, резюме и достижения удаляются;
  - открытые приглашения истекают, согласия отзываются;
  - обезличенная статистика тестов остаётся для калибровки.
- Кандидат заранее предупреждён о журнале попытки: подтверждение перед стартом теста и правила на странице выбора. Автоматических банов нет — решение по подозрительной попытке принимает человек.

## Секреты

Все ключи передаются только через переменные окружения (`.env.example` описывает каждую). Ключ RouterAI используется только на сервере (`server/llm`). Каталог `.env*` в `.gitignore`.

## Файлы

- PDF-резюме и сертификаты: проверка сигнатуры файла (`%PDF-`, PNG, JPEG), лимит 4 МБ.
- Хранение в Vercel Blob со случайным суффиксом; URL не отдаётся другим пользователям.
- **Ограничение:** Blob-объекты публичны по неугадываемому URL — для продакшена нужен приватный бакет или подписанные ссылки.
