# Ограничения прототипа и план развития

## Честные ограничения

| Область | Ограничение | Что с этим делать |
|---|---|---|
| Проверка кода | Код выполняется в браузере: скорость и память не проверяются, исполнение технически можно вынести за пределы браузера. Верный ответ всё равно требует решить задачу на свежих скрытых входах | Серверная песочница (Judge0 / Piston на VPS) для задач с лимитами времени и памяти; интерфейс проверки уже готов |
| Точность грейда | На синтетике ~76% совпадений с истинным уровнем, ошибки на одну ступень у границ грейдов; CAT почти всегда использует 18 заданий | Расширять банк (больше информативных заданий у каждого порога), калибровать на реальных ответах, ввести «пограничную зону» с перепроверкой |
| Калибровка | Стартовые a, b — экспертные; калибровка проверена на синтетике | Копить реальные ответы; пересчёт `npm run calibrate` по расписанию вне Vercel |
| Ловушки | Доли срабатывания ИИ-ассистентов в валидации — допущения | Измерить на пилоте и настроить веса в `server/testing/trust.ts` |
| Полноэкранный режим | iPhone Safari не поддерживает Fullscreen API для страницы — тест идёт без него (это не штрафуется) | Для мобильных — короче тест и больший вес сигналов фокуса |
| Rate limit | Без Upstash лимиты in-memory действуют на один serverless-инстанс | Подключить Upstash Redis (бесплатный тариф) |
| Файлы | Vercel Blob — публичные объекты по неугадываемому URL | Приватное хранилище или подписанные ссылки |
| Реестр ФСП | Мок с той же структурой данных | `HttpFspRegistry` + вебхуки (см. `fsp-integration.md`) |
| Keycloak | Профиль docker-compose и провайдер готовы; полный OIDC-обмен в среде разработки не прогнан (Docker Hub ограничивал загрузку образов) | Проверить `docker compose --profile keycloak up` локально |
| GitHub | Без OAuth-привязки логин заявляется кандидатом | OAuth GitHub App, проверка `viewer.login` |
| Сертификаты | Подпись PDF обнаруживается, но цепочка сертификатов не проверяется | Проверка подписи (PKCS#7) и QR/ID организатора через API организаторов |
| Семантический подбор | Сходство «задача ↔ опыт» через эмбеддинги не реализовано (необязательный пункт ТЗ); модели эмбеддингов в RouterAI доступны, таблица `embeddings` в схеме есть | Добавить компоненту с малым весом и кешем эмбеддингов |
| Регулярные задачи | Выдаются лениво при входе кандидата, без расписания; задачи по эталону проще слить, поэтому они влияют только на свежесть и доводы, а не на грейд | Cron-выдача и напоминания; параметризованные задачи с исполнением кода (см. `challenges.md`) |
| Доступ к стенду | Домен `*.vercel.app` из части российских сетей открывается только через VPN (согласовано с организаторами) | Российский хостинг или собственный домен; локальный запуск — `docker compose up` |

## План развития

1. **Пилот с реальными кандидатами ФСП**: сбор ответов, калибровка, настройка весов индекса доверия и скоринга по откликам работодателей (какие приглашения принимают).
2. **Банк заданий**: по 60+ шаблонов на специализацию; Mobile, DevOps, аналитики; совместная разработка шаблонов с экспертами ФСП и ревью.
3. **Серверная песочница** для задач с ограничениями ресурсов и для повторной проверки кода модератором.
4. **Реальная интеграция с ФСП**: OIDC «ФСП ID», REST-реестр, вебхуки результатов.
5. **Подбор**: эмбеддинги «описание задачи ↔ опыт», обучение весов на исходах приглашений (learning-to-rank) с сохранением объяснимости через доводы.
6. **Работодатели**: верификация по ИНН, командные аккаунты, шаблоны приглашений, аналитика воронки.
